**Concerns:** `pushword/admin`, `pushword/admin-block-editor`, `pushword/advanced-main-image`, `pushword/api`, `pushword/conversation`, `pushword/core`, `pushword/flat`, `pushword/installer`, `pushword/link-improver`, `pushword/newsletter`, `pushword/page-scanner`, `pushword/page-update-notifier`, `pushword/quiz`, `pushword/repurpose`, `pushword/search`, `pushword/snippet`, `pushword/static-generator`, `pushword/template-editor`, `pushword/version`, `@pushword/js-helper`

## Bundles register themselves now

Pushword ships no Flex recipe, so nothing ever added a bundle to `config/bundles.php`:
`composer require pushword/<bundle>` installed code the app never loaded, and the route
import the same step wrote pointed at a bundle the kernel did not know. Half the bundles
had no install step at all.

Every bundle now registers itself and imports its own routes at install time. Nothing to
run — but the next `composer update` may edit two files for the packages that never had
an install step (api, flat, link-improver, newsletter, page-update-notifier, quiz,
repurpose, search, snippet):

- `config/bundles.php` gains the bundle, unless it is already there.
- `config/routes.yaml` gains the bundle's route import, unless the file already
  references that bundle in any form — a different key, double quotes, an attribute
  import of its controller directory all count as "already imported".

If you deliberately keep one of those bundles' routes out of your app, check
`config/routes.yaml` after updating.

`Pushword\Installer\PostInstall` grew the two helpers doing it, `registerBundle()` and
`importRoutes()`, and now runs `pushword/core`'s install step last, so its
`doctrine:schema:update` and `assets:install` see every other bundle registered.

## The markdown body is edited in Monaco, and EasyMDE is gone

The page body used the EasyMDE editor; it now uses Monaco, the editor the admin already
ships for Twig, YAML and JSON — same toolbar buttons, plus list continuation on `Enter`,
`Alt+C` for task items, `Ctrl+Shift+]`/`[` for heading levels, and pasting a URL onto
selected text to link it. `packages/docs/content/extension/admin.md` lists the keys.

Two things go away with it: the **side-by-side live preview** and its fullscreen
companion (the fullscreen button stays), and inline image rendering inside the editor.

Nothing to run — `composer update` reinstalls the assets. Two cases need a look:

- A site importing `@pwAdmin/admin.easymde-editor.css`, or reaching for `window.EasyMDE`
  or the `.editor-preview-side` / `.EasyMDEContainer` classes in its own admin CSS or JS,
  loses those. The editor now renders as `.pw-md` (`.pw-md__toolbar`, `.pw-md__host`,
  `.pw-md__status`).
- A site overriding `@pwAdmin/layout.html.twig` should drop any hand-written
  `<script src="/bundles/pushwordadmin/monaco/app.js">`: `admin.js` now fetches Monaco
  itself, and only on the pages holding a field that needs it, from the URL the dashboard
  publishes as `window.pwMonacoUrl`. Pages that used to pull those few megabytes for
  nothing no longer do.

`easymde` and its `codemirror` dependency are dropped from `@pushword/js-helper`, and the
`easymde-hack` build step — which patched `node_modules` to add a Twig mode — is gone with
them.
